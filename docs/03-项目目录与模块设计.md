## 1. 目录搭建状态与实现边界

当前已按以下蓝图建立全部工程目录，设计及协作分册位于 `docs/`，项目入口为根目录 `README.md`。空目录使用 `.gitkeep` 保留；`build/`、`runs/` 的未来产物通过根目录 `.gitignore` 排除。参考资料保持原位只读，导航与来源链接已按迁移后的路径更新。

本次只搭建目录，未创建头文件、实现文件、测试程序或构建脚本。下方 `CMakeLists.txt` 是唯一尚未创建的规划文件，留待后续构建系统实施阶段提供有效内容，不以空文件冒充可构建工程。

## 3. 模块职责与依赖

| 模块 | 职责 | 允许依赖 | 禁止行为 |
|---|---|---|---|
| core | 值类型、对象不变量、单位和几何 | C++ 标准库 | 引入 Qt、文件格式解析、算法流程 |
| io | 解析、模型适配、结果读写 | core、所需第三方格式库 | 隐式优化坐标、直接更新 GUI |
| global | 连续全局布局 | core、FFTW3 | 修改固定对象或拓扑 |
| legalization | 独立检查与位置修复 | core、analysis 的纯计算接口 | 用“算法结束”代替检查通过 |
| analysis | 指标与比较 | core | 持有 GUI 状态或隐式修改快照 |
| visualization | 图像和 GDSII，几何适配 | core、analysis、CImg、Limbo GDS | 从屏幕像素反推布局位置 |
| application | 请求校验、阶段编排、控制、结果身份 | 上述业务模块 | Qt 对象穿透到算法核心 |
| cli/gui | 交互与展示 | application、只读 core、analysis | 各自维护不同的算法定义 |

依赖方向为“入口 → 应用服务 → 业务模块 → core”，不出现反向 include。Qt 的 signal/slot 在 GUI 桥接层结束，核心只接收普通 C++ 请求、回调与控制令牌。

## 4. 构建目标规划

未来划分 `placement_core`、`placement_algorithms`、`placement_io`、`placement_visualization`、`placement_application` 库，以及 `placement_cli`、可选 `placement_gui`。`BUILD_GUI` 默认开启；关闭后不查找 Qt。`BUILD_TESTING` 控制 GoogleTest/CTest；GUI 打开时才启用 Qt Test。构建选项和依赖失败在配置阶段明确报告，不静默删掉必需功能。

FFTW 仅被数值适配模块持有；Limbo parser 和 GDS writer 依赖按组件隔离，不因使用 GDS 强迫核心链接全部解析器。CImg 以禁用显示窗口的方式使用 BMP 输出，不引入 X11 作为 CLI 必需项。

## 5. 数据与运行结果组织

输入数据通过外部路径引用，不复制数十 MB 的 nets 文件到版本库。每个数据清单登记源路径、大小、SHA-256、对象统计和单位声明。使用相对项目清单路径解析关联输入，算法不依赖进程工作目录。

未来每次运行使用 `runs/<run-id>/`，其中包含 `manifest.json`、`effective-config.json`、`input-audit.json`、`metrics.csv`、`events.jsonl`、`stages/<stage>/placement.json`、`stages/<stage>/violations.json`、`images/<stage>.bmp`、`gds/<stage>.gds`。若使用物理比例，还保存单位来源；缺少比例时明确采用显示映射，不声称是真实工艺尺寸。

阶段名称固定为 `initial`、`global`、`macro_legal`、`standard_legal`。只有检查/阶段提交成功才能创建对应的正式阶段记录；中途预览使用 `preview` 身份，不与成功阶段混用。

## 6. 资源与变更管理

拓扑由数据库拥有，算法位置缓冲由当前任务拥有，只读快照通过共享常量对象传递。禁止把裸指针地址当作对象 ID。第三方内部类型不得出现在稳定公共头文件中。

每次变更按“需求编号 → 设计章节 → 模块 → 测试编号”记录。原始示例项目仅用来理解 CImg 与对象概念，不直接复制其裸指针管理、硬编码输入、构建缓存和可执行文件。
