## 实现范围

| 模块 | 实际入口 | 实现内容 |
|---|---|---|
| 领域模型 | `include/placement/core/model.hpp`、`src/core` | 稳定ID、八方向、物理容差、单位、只读拓扑/快照、固定性及协作令牌 |
| 输入 | `src/io/bookshelf`、`src/io/lefdef` | 六文件关联、权重/引用审计、SHA-256、Limbo所附LEF/DEF 5.8解析器适配 |
| 全局布局 | `src/global` | 精确WA梯度、守恒平滑密度、静态并集、filler、FFTW正交DCT、离散泊松、投影Nesterov |
| 合法化 | `src/legalization` | 保持方向的宏SA、行障碍切分、整站点Abacus、独立复检后发布 |
| 分析/导出 | `src/analysis`、`src/visualization` | 真实HPWL与分类位移、完整违规计数、有界详情、CImg BMP、真实GDSII及量化审计 |
| 应用/CLI | `src/application`、`src/cli` | 配置优先级、独占运行、四阶段快照、事件/指标流、原子提交、重载及明确退出码 |
| GUI | `src/gui` | Qt Widgets、后台任务、安全点暂停取消、容量1预览、阶段比较、分块/LOD、命中、属性和独立导出 |

公共接口不暴露 Qt、FFTW、Limbo、CImg 类型。真实实例与任务私有 filler 分离；GUI 热图明确为真实与静态电荷之和，不含未存入快照的 filler。

已按实施契约统一几何距离容差和 DU 站点残差。碰撞与边界采用 `min(εg, 10⁻⁶ pmin)`，无行时用 εg；面积仍统计真实交集。行切分保留原始网格。初始 overflow 达标可直接完成，否则连续五轮达标才收敛；配置中的 `convergence_window` 固定为5。达到迭代上限的结论会跨后续合法化保留。

LEF/DEF 原点有一项文档勘误：DEF 位置对齐方向后 SIZE 框左下角，LEF ORIGIN 先作用于引脚几何；见[04分册](04-总体技术与接口设计.md)。八方向和非零 ORIGIN 已用独立世界坐标真值验证。

## 构建及自动测试

以下命令从仓库根 `code/` 执行：

```sh
python3 cmake/bootstrap_deps.py --offline
cmake -S . -B /tmp/school3-headless -DCMAKE_BUILD_TYPE=Release \
  -DBUILD_GUI=OFF -DBUILD_TESTING=ON -DPLACEMENT_DEPS_PREFIX=/tmp/school3-deps/usr
cmake --build /tmp/school3-headless -j 2
env -u DISPLAY ctest --test-dir /tmp/school3-headless --output-on-failure
cmake -S . -B /tmp/school3-gui -DCMAKE_BUILD_TYPE=Release \
  -DBUILD_GUI=ON -DBUILD_TESTING=ON -DPLACEMENT_DEPS_PREFIX=/tmp/school3-deps/usr
cmake --build /tmp/school3-gui -j 2
ctest --test-dir /tmp/school3-gui --output-on-failure
/tmp/school3-gui/gui_test -platform offscreen
```

实际结果：headless **84/84** CTest、GUI **85/85** CTest 全部通过，Qt Test 内部 **17/17**（含 init/cleanup）通过。

最终结果由同目录 `runs/acceptance/headless-ctest.txt`、`gui-ctest.txt`、`qt-test.txt` 保存。无 Qt 配置完全跳过 Qt 查找；CImg 禁用显示窗口。Qt Test 的 init/cleanup 包含在其内部统计中，CTest 中整个 Qt Test 程序仅算一项。

独立判据包括：有限差分梯度、离散 Neumann 算子、DCT 往返、真实电荷积分、整数站点小例穷举、独立二进制 GDS XY 解码、KLayout 回读。密集碰撞回归使用 20000 个重合实体，完整计数为 199990000，详情仍按稳定ID排序且有界。非单位 pitch、阈值两侧、薄长交集、固定体/硬阻挡并集和非默认配置均有回归。

状态与故障测试覆盖真实算法取消、数值失败保留最后完整轮、伪合法结果重载拒绝、原子写中途失败/取消、GDS伴随元数据失败保护、暂停导出、导出拒绝覆盖不影响主任务、旧身份事件、唯一终态和协作关闭。CLI 脚本实际验证退出码3、显式继续仍保留未收敛结论、重载后独立复检和缺前置快照拒绝。

早期 core/analysis/legalization 合并测试另以 `-Wall -Wextra -Wpedantic -Werror` 和 ASan/UBSan 执行通过。当前环境 LeakSanitizer 的 ptrace 条件不满足，检测时使用 `detect_leaks=0`；不声称通过泄漏检测。第三方 Bison 文法仍有其原有弃用/修复提示，未修改参考源码。

## 端到端与独立回读

```sh
env -u DISPLAY /tmp/school3-headless/placement_cli run \
  --aux '../综合设计III参考资料/任务2参考/BookShelf格式的解析/thin1/thin1.aux' \
  --stage all --output runs/acceptance/thin1-final
env -u DISPLAY /tmp/school3-headless/placement_cli run \
  --lef tests/fixtures/lefdef/tiny.lef --def tests/fixtures/lefdef/tiny.def \
  --stage all --set overflow_stop=0.11 --output runs/acceptance/lefdef-final
```

两次成功运行均返回0，四阶段身份、CSV、配置/seed与独立报告的逐字段审计另见 `four-stage-audit.json`；保存 initial/global/macro_legal/standard_legal、每阶段独立违规报告、BMP/GDS、完整有效配置、输入指纹及 manifest。thin1 使用默认配置，global 初始 overflow=0，按明确例外直接收敛；最终标准布局独立检查零违规。

配套 LEF/DEF 微型例必须区分两次实际结果：默认 overflow_stop=0.10 的运行在第264轮附近触发密度系数触顶停滞，返回4，保留 initial 和完整失败候选，记录在 `lefdef-verified/`；显式阈值0.11的运行初始 overflow≈0.106877，按初始达标例外完成四阶段，最终独立合法。此成功记录证明输入、服务和结果链路，不作为该夹具默认参数下优化必收敛的证明。

原 `cn.lef` 与 `ispd19_test1.input.def` 的全部93种被引用 master 均不匹配；实际 CLI 返回2及 `REFERENCE_MISSING`，不是成功适配夹具。新增 `tests/fixtures/input-equivalence` 逐节点/引脚/网络核对两种格式等价，独立真值为 HPWL=15、加权HPWL=20。

KLayout 已分别回读 thin1 和配套 LEF/DEF 成功运行的全部四阶段，共8份 GDS，返回码均为0；按源 placement 中的实例尺寸、方向、位置和硬阻挡独立核对单位、图层、BOUNDARY 框。命令形式：

```sh
LD_LIBRARY_PATH=/tmp/school3-deps/usr/lib/klayout:/tmp/school3-deps/usr/lib/x86_64-linux-gnu \
  /tmp/school3-deps/usr/lib/klayout/klayout -b -r tests/integration/klayout_verify.py \
  -rd gds_path=运行目录/gds/standard_legal.gds \
  -rd source_path=运行目录/stages/standard_legal/placement.json \
  -rd output_path=运行目录/gds/standard_legal.readback.json
```

汇总位于 `runs/acceptance/klayout-stage-readbacks.txt`。本机 KLayout 启动时还会输出缺少 Ruby pathname 的可选宏警告，Python pya 回读脚本实际执行并返回0；未把警告当作读回失败或当作人工查看证据。

同输入/有效配置/seed 的同一二进制的两次 thin1 运行另存 `thin1-repeat/` 与 `thin1-repeat2/`，逐阶段比较节点、方向、全部数学指标、终止原因及调整记录，仅排除 runId 和实测耗时；对照记录位于 `reproducibility.json`。重载检查需要同时提供原始输入，以核对指纹和完整网络拓扑。
